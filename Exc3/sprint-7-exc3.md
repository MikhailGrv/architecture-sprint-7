# Спринт 7 задание 3


## Сформируйте список требований, которым должны удовлетворить внешние интеграции. Для этого:

опишите требования к безопасности,
### I. Управление доступом

Все запросы внутри системы должны быть идентифицированы и аутентифицированны
Все предоставляемые API должны проверять запросы на предмет аутентификации и Авторизации
Должна быть разработана Ролдевая модель доступов
Использовать 2х факторную авторизацию для клиентов (биометрия/пароль/телефон)
Использовать SSL (TLS 1.2/1.3 для связи моб приложения с APIGateway)
Использовать TLS/mTLS для связи с устройствами
Использовать белый список IP устройств для связи с API Gateway
Доступ к СУБД систем должен осуществляться на основе ролевой модели по принципу наименьших прав

### II. Безопасность данных
Разделить данные на категории
Для категории Конфиденциальные данные:
    - работу с данными/хранение выделить в отдельную сетевую зону с ограниченным доступом
    - ограчничить доступ в зону только для необходимых сервисов. Доступ из других зон только для разрешенных взаимодейвствий. 
    - шифровать данные при хранении
    - использовать шифрование для передачи данных
    - контролировать/аудировать доступ к данным
    - все запросы должны быть авторизованы 
Для зоны Внутренние данные:
    - использовать шифрование для передачи данных
    - все запросы должны быть авторизованы 
    - ограничить доступ из других зон. Доступ из других зон только для разрешенных взаимодейвствий 
    - конфеденциальные данные только передавать. хранить запрещено.
    - передача данных должна шифроваться
    - хренение данных допустимо в незашифрованном виде
Для зоны DMZ:
    - разрешен доступ из-вне организации строго к API Gateway
    - настроены политики аудирования трафика
    - настроена защита от DDoS
    - закрыты порты (которые не используются для разрешенныхъ действий)
    - все запросы должны проходить идентификацию и авторизацию для передачи дальше
    - все запросы должнышифроваться
  

### III. Защита инфраструктуры
Для категории Конфиденциальные данные
    - Взаимодействие только с зоной Внутренние данные только по разрешенным взаимодействиям
    - все порты закрыты, которые не участвуют в разрешенных взаимодействиях
    - настроен мониторинг подозрительной активности 
Для зоны Внутренние данные
    - Взаимодействие только с зоной Конфиденциальные данные и DMZ только по разрешенным взаимодействиям
    - все порты закрыты, которые не участвуют в разрешенных взаимодействиях
    - настроен мониторинг подозрительной активности 
Для зоны DMZ:
    - настроена защита от DDoS
    - закрыты порты (которые не используются для разрешенныхъ действий)
    - все запросы должны проходить идентификацию и авторизацию для передачи дальше
    - настроен мониторинг подозрительной активности
